# A03 목적별 자료 추출 Agent

> 근거: `Agent정의서_3_목적별자료추출.docx` · 앞 Agent: A02 최신값 판정·DB 갱신 · 뒤 Agent: A04 보고서 초안 작성

| 구분 | 내용 |
|---|---|
| 목적 | 담당자가 정한 보고서 목적에 맞춰 DB에서 필요한 항목을 골라, 출처와 기준일이 붙은 **자료표**로 만든다 |
| 시작 조건 | 담당자가 목적(보고 유형·대상 사업, 또는 목적 문장·질문)을 입력했고 A02 DB 갱신이 끝났을 때 |
| 입력 | ① 보고서 목적 ② 갱신된 DB(최신값·출처·기준일·미확정 표시) |
| 출력 | 자료표: 지구·시설·항목·값·상태·판정 유형·문서 단계·문서 일자·출처 + **부족·미확정 표시** → A04가 읽음, 엑셀로도 내려받기 |
| 사람 개입 | 목적 입력은 담당자. 자료표 별도 승인은 없고 A04 초안 최종 검토 때 함께 확인 |
| 도구 | DB 조회, AI 언어모델(키 있을 때 목적 문장 → 항목 고르기, 값은 바꾸지 않음) 또는 키워드 규칙 |

## 수행 단계와 코드
| 단계 | 하는 일 | 코드 |
|---|---|---|
| ① | 목적을 읽고 필요한 항목을 정한다 | 대상 사업을 고르면 그 사업 전체 항목 / 목적 문장이면 `query.select`(AI 또는 키워드) |
| ② | DB에서 값을 가져온다 | A02 `store.facts` 결과를 받음 |
| ③ | 값이 없거나 충돌이 안 풀린 항목은 "부족·미확정" 표시 | `agent.run`의 `lacking`, 자료표 '표시' 열 |
| ④ | 출처·기준일을 유지한 채 자료표로 | `query.to_row` |
| ⑤ | A04에 넘긴다 | `agent.run`의 반환값을 A04 `agent.run`에 그대로 |

## 입구 함수 (`agent.py`)
```python
from agents.a03_query import agent as A03
res = A03.run(facts, '현안사항 보고', facilities=['환승센터', ...])  # 대상 사업을 고른 경우
res = A03.run(facts, '철도 사업비 현황')                             # 목적 문장만 준 경우
res['table'], res['lacking'], res['basis']
A03.to_excel(res, '제목', sources)                                   # 자료표 엑셀(값마다 출처)
A03.search('주민 반대로 지연되는 사업 있어?', facts, CAT)            # 💬 챗봇
A03.projects(facts, CAT)                                             # 사업 단위 요약(대시보드·통합 비교)
```

## 같은 DB 조회 기능으로 함께 맡는 일
- 💬 챗봇: 질문 → 검색 조건(지구·유형·사업비 범위·시행주체·현안 낱말) → 결과 표. 숫자는 DB 값만 씁니다.
- 💾 DB › 🔎 통합 비교: 여러 사업지구 사업을 한 표로 보고 필터합니다.

## 정의서와 다른 점 (현재 구현)
- 📝 보고서 작성 화면에서는 목적을 "보고 유형 + 대상 사업"으로 받습니다. 목적 문장을 받아 항목을 고르는 기능(`run(facts, '목적 문장')`)은 코드와 시험에 있지만, 화면에서는 챗봇 검색에만 쓰입니다.
